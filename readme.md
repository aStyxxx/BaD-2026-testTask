# Однорядний цифровий пазл (Longest Digital Puzzle Solver)

Рішення задачі з пошуку найдовшої послідовності цифрових фрагментів, які з'єднуються між собою за першими та останніми двома цифрами (кожен фрагмент може бути використаний не більше одного разу).

## Опис алгоритму та оптимізацій

Задачу зведено до класичної задачі теорії графів — **пошуку найдовшого простого реберного шляху (Longest Trail)** в орієнтованому мультиграфі (графі Де Брейна):

1. **Модель графа:**
   * **Вершини (`00`..`99`):** усі можливі двозначні комбінації цифр на стиках фрагментів (фіксовано 100 вершин).
   * **Орієнтовані ребра:** самі числові фрагменти з вхідного файлу, які з'єднують вершину-префікс (перші 2 цифри) із вершиною-суфіксом (останні 2 цифри). Граф представлено списками суміжності (`std::vector<Edge> adj[100]`), що дозволяє побудувати його за лінійний час $O(N)$.

2. **Пошук та інженерні оптимізації (DFS + Backtracking + Branch and Bound):**
   * **Відсікання симетричних переходів (Symmetry Breaking):** під час побудови графа списки суміжності кожної вершини сортуються за вершиною призначення (`edge.to`). Завдяки цьому паралельні ребра (різні фрагменти з однаковими першими й останніми двома цифрами) стають сусідніми в пам'яті. У рекурсії це дозволяє за $O(1)$ пам'яті (однією змінною `lastTriedTo`) пропускати дублікати переходів на поточному рівні, не виділяючи масив відвіданих сусідів на стеку.
   * **Метод гілок і меж (Branch and Bound):** перед подальшим розгалуженням у DFS оцінюється верхня межа (Upper Bound) кількості невикористаних ребер, які взагалі досяжні з поточної вершини. Якщо сума поточної довжини шляху та всіх досяжних ребер не перевищує вже знайдений рекорд (`bestPath.size()`), гілка миттєво відсікається.
   * **Timestamping (`visited_epoch`):** для перевірки досяжності вершин використовується масив епох (`visited_epoch[v] == current_epoch`) замість занулення масиву `visited` (`memset` / `std::fill`). Це зводить накладні витрати на ініціалізацію кожного допоміжного обходу до $O(1)$.
   * **Оптимізація типів даних:** для відстеження використаних ребер замість бітової спеціалізації `std::vector<bool>` застосовано `std::vector<uint8_t>`, що усуває зайві побітові операції у гарячому циклі рекурсії.

## Компіляція та запуск (Обмеження #1)

Програма написана на стандартному **C++ (C++11 і вище)**, не використовує сторонніх чи пропрієтарних бібліотек і може бути запущена як через середовище **Microsoft Visual Studio**, так і з командного рядка на Windows, Linux або macOS.

### Варіант 1: Запуск через Microsoft Visual Studio
1. Відкрийте файл проєкту `PuzzleProblemSolution_Bad.vcxproj` (або `.sln` файл на рівень вище) у **Visual Studio**.
2. Оберіть конфігурацію **Release** (або **Debug**) та платформу **x64**.
3. Натисніть `Ctrl + F5` (Start Without Debugging) для компіляції та запуску. Програма автоматично зчитає файл `data.txt` із папки проєкту.

### Варіант 2: Компіляція та запуск із командного рядка

**За допомогою GCC / MinGW (Linux, macOS, Windows):**
```bash
g++ -std=c++17 -O3 PuzzleProblemSolution_BaD.cpp -o solver
```

**За допомогою Clang:**
```bash
clang++ -std=c++17 -O3 PuzzleProblemSolution_BaD.cpp -o solver
```

**За допомогою MSVC (Developer Command Prompt for Visual Studio на Windows):**
```cmd
cl /EHsc /O2 /std:c++17 PuzzleProblemSolution_BaD.cpp /Fe:solver.exe
```

### Запуск виконуваного файлу

За замовчуванням програма шукає файл `data.txt` у поточній директорії:
```bash
./solver
```
*(На Windows у консольній оболонці: `solver.exe`)*

Щоб запустити програму з **будь-яким іншим файлом фрагментів**, передайте шлях до нього першим аргументом командного рядка:
```bash
./solver custom_fragments.txt
```
